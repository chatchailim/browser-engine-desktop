# ควบคุม Windows แบบมีคนกำกับ — รุ่นทดลอง

สำหรับการทดสอบตอนนี้ ใช้ [คู่มือเลือก Notepad ด้วยหมายเลข](PICK-NOTEPAD-TH.md) และ OPEN-LIVE-TEST.cmd รุ่นใหม่ ไม่ต้องจับหน้าต่างแข่งกับเวลานับถอยหลัง วิธี --select-foreground ด้านล่างยังมีไว้สำหรับความเข้ากันได้กับรุ่นเดิม

เพิ่มตามคำขอผู้ใช้ 25 กันยายน 2026: คลิกซ้าย พิมพ์ Unicode/ภาษาไทย ลากภายในหน้าต่างเดียว และกดคีย์ทีละปุ่ม มี native backend แล้ว แต่ยังไม่ผ่าน live input acceptance บน Windows จริง จึงยังไม่รับรอง production หรือความเร็วเหนือรุ่นเดิม

โหมดนี้แยกจาก WindowsUIAAdapter แบบอ่านอย่างเดียว ไม่เปิดผ่าน HTTP หรือ AI planner และไม่เปลี่ยน config เดิม การเริ่ม START-LOCAL.cmd ไม่เปิดสิทธิ์ desktop input

## การควบคุม

- ปิดโดยค่าเริ่มต้น ต้องระบุ `--enable-input` พร้อม executable path แบบเต็ม และเลือกหน้าต่างอย่างเจาะจงทุกเซสชัน ไม่มี wildcard
- ยืนยัน ENABLE เพื่อเปิดเซสชัน แล้วอนุมัติคำสั่งที่แสดงด้วยรหัสครั้งเดียวต่อคำสั่ง อายุ 30 วินาที เซสชันหมดอายุใน 5 นาที หรือครบ 30 คำสั่ง ไม่มีอนุมัติแบบเหมา
- ผูก HWND, PID, creation time, executable path และ UIA runtime ID; ถือ process handle ตลอดเซสชัน ถ้า identity/ตำแหน่ง/ขนาดหน้าต่างเปลี่ยนให้หยุด
- ต้องเป็นหน้าต่าง foreground จริง จุดคลิกต้องอยู่ใน client area และไม่ถูกหน้าต่างอื่นบัง ลากได้ภายในกรอบเดิมเท่านั้น ใช้พิกัด physical screen pixels และ DPI awareness
- ตรวจ secure desktop, process ยกระดับสิทธิ์, UAC/credential windows, password/OTP metadata; ข้อมูลตรวจไม่ได้ให้ปฏิเสธ ไม่อ่านค่าในช่องรหัสผ่าน
- บล็อก shell/terminal, regedit, mmc, Task Manager และคีย์ลัด Ctrl/Alt/Win; ไม่มี clipboard, script หรือคำสั่งระบบ คีย์ที่มี: LEFT RIGHT UP DOWN HOME END BACKSPACE DELETE TAB ENTER ESC
- พิมพ์ได้ไม่เกิน 500 ตัวอักษรต่อคำสั่ง ไม่รับ newline/control characters ใช้คำสั่ง key แยกเมื่อต้องการ Enter/Tab
- ล็อก native input session ด้วย named mutex ไม่เปิดหลายคอนโซลพร้อมกัน ตรวจ control.json paused และไฟล์หยุดก่อนแต่ละช่วง input
- บันทึก intent ก่อนทำ ถ้าบันทึกไม่ได้จะไม่ทำ; audit เก็บชนิดคำสั่ง/เวลา/ลำดับ/สถานะ ไม่เก็บข้อความที่พิมพ์หรือ hash ของข้อความ
- ถ้าคำสั่งล้มเหลวกลางทาง จะหยุดทั้งเซสชันและไม่ลองซ้ำอัตโนมัติ พยายามปล่อยปุ่ม synthetic ใน finally

## เปิดใช้สำหรับทดสอบ

ใช้เอกสารใหม่ที่ทิ้งได้ใน Notepad ก่อน ไม่เปิดคอนโซลเป็น Administrator หยุด browser task/automation อื่นก่อนใช้ desktop input — named mutex นี้ไม่ล็อกเครื่องมือภายนอกหรือ browser engine

เปิด PowerShell ที่โฟลเดอร์บริการ แล้วเรียกด้วย executable path จริงของแอป เช่น (ตำแหน่ง Notepad อาจต่างกัน โดยเฉพาะ Windows 11):

```powershell
.\DESKTOP-CONTROL.cmd --enable-input --select-foreground --allow-exe "C:\Windows\System32\notepad.exe"
```

หาก path ไม่ตรงโปรเซสจริงจะปฏิเสธ ไม่เดาให้เอง ดู path ได้จาก Task Manager > Details > Open file location หรือ Properties ของแอป สามารถใช้ `--hwnd <หมายเลข>` แทน `--select-foreground` หากทราบ top-level HWND แล้ว

หลังพิมพ์ ENABLE มีเวลานับถอยหลัง 15 วินาทีให้คลิกภายในหน้าต่างเป้าหมายและคงโฟกัสไว้จนจับหน้าต่างเสร็จ กลับมาคอนโซลเพื่อป้อน JSON ทีละคำสั่ง ระบบแสดงคำสั่งจริงให้ตรวจและให้พิมพ์รหัสอนุมัติ จากนั้นมีเวลา 5 วินาทีให้กลับไปโฟกัสหน้าต่างเดิมก่อนทำงาน

```json
{"kind":"type","args":["ทดสอบข้อความในเอกสารใหม่"]}
{"kind":"key","args":["LEFT"]}
{"kind":"click","args":[450,350]}
{"kind":"drag","args":[450,350,600,350]}
```

ตัวเลขตัวอย่างไม่ใช่พิกัดที่ตรวจแล้ว ต้องเปลี่ยนตามตำแหน่งหน้าต่างจริง ห้ามคัดลอกไปอนุมัติโดยไม่ได้ดูเป้าหมาย ไม่มีการส่งคำสั่งใดจากคู่มือนี้อัตโนมัติ

เมื่อขึ้น `input_submitted` หมายถึงส่งอินพุตแล้ว ไม่ใช่ยืนยันว่าผลลัพธ์ถูกต้อง ผู้ใช้ต้องดูผลบนหน้าจอก่อนคำสั่งถัดไป บันทึกอยู่ `data/desktop-input/session-*.jsonl` ไม่บันทึก plaintext แต่ข้อความคำสั่งยังเห็นได้ในหน้าคอนโซล จึงห้ามพิมพ์ข้อมูลลับ

## หยุด

- กด Escape ค้างระหว่าง input เพื่อให้ guard รอบถัดไปหยุด หรือกลับคอนโซลแล้ว Ctrl+C / พิมพ์ STOP
- ดับเบิลคลิก `STOP-DESKTOP.cmd` เพื่อสร้างไฟล์หยุดถาวร หรือกำหนด `coordination/codex-anti/control.json` ให้ paused เป็น true
- หลังใช้ไฟล์หยุด ต้องตรวจผลค้างด้วยตนเองแล้วลบ `service/DESKTOP-STOP` ก่อนเปิดเซสชันใหม่ ระบบไม่ลบให้เอง
- การหยุดเป็นแบบตรวจระหว่างคำสั่งย่อย ไม่สามารถยกเลิก event ที่ส่งไปแล้วหรือ COM call ที่ค้างอยู่ได้ การฆ่าโปรเซส/เครื่องดับอาจทำให้ finally ไม่ได้ทำงาน หากมีปุ่มค้างให้ผู้ใช้ปล่อยปุ่มด้วยตนเอง ห้ามเริ่มวนซ้ำ

## ข้อจำกัดที่ยังต้องทดสอบจริง

SendInput เป็น global input มีโอกาสหน้าต่างเปลี่ยนในช่วงหลังตรวจและก่อนส่ง event จึงลดความเสี่ยงได้แต่รับประกันว่าไม่มี focus race ไม่ได้ โปรแกรมอื่นหรือผู้ใช้ไม่ควรแย่งควบคุมระหว่างทำงาน UIA password metadata ที่แอปไม่เปิดเผยอาจตรวจไม่พบ ห้ามใช้กับข้อมูลรับรอง/แอปการเงิน/งานส่งเผยแพร่หรือข้อมูลสำคัญในรุ่นทดลองนี้

ก่อนรับเป็นบริการจริง: ซ้อมกับเอกสารใหม่ทั้งคลิก พิมพ์ไทย/emoji ลากเลือกข้อความ กดลูกศร และหยุดระหว่างพิมพ์/ลาก; ตรวจหน้าต่างอื่น foreground, executable ผิด, popup/ช่องรหัสผ่าน, DPI หลายจอ, การปล่อยปุ่มและหยุดค้าง ยืนยันผลด้วยหน้าจอจริง ไม่ใช้จำนวน unit tests แทน live acceptance

รอบพัฒนานี้ใช้ native-boundary mocks ทั้งหมด ไม่มีการคลิก/พิมพ์/ลากจริงบนเครื่องผู้ใช้ ไม่มี Suno/credits/model calls และไม่มี browser-desktop autonomous handoff
