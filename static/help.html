บทที่ 0 — ระบบนี้คืออะไร

ระบบนี้คือ "ผู้ช่วย AI ที่ลงมือทำแทนคุณได้จริง" บนเครื่อง Windows ของคุณเอง — ต่างจาก ChatGPT ที่เสนอแนะ ระบบนี้ลงมือทำให้จบ แต่ทุกการกระทำมีรอยเท้า+ลายเซ็นกันแก้+กู้คืนได้

ความสามารถคุณสั่งAI ทำ
🌐 Browser use"เปิดเว็บ X หาข้อมูล Y"ไข่ คลิก อ่าน ดึงคำตอบ พร้อมหลักฐาน
🖥️ Computer use"เปิดโน้ตแพด พิมพ์ 3 บรรทัด"จับหน้าจอ วางแผน ลงมือ — คุณอนุมัติก่อนทุกงาน
⌨️ Shell use (admin)"รันคำสั่งนี้"รันจริงใน sandbox + rollback ได้เสมอ

ตัวเลขจริงที่พิสูจน์แล้ว: งานเดิมเร็วขึ้น 2.1–4 เท่า (21.9วิ → 5.4วิ) · เทสต์ 194/194 · งานแคช = "สูตรวิธีทำ" ไม่ใช่คำตอบ — คำตอบยังมาจากแหล่งจริงทุกครั้ง

บทที่ 1 — เริ่มระบบ 5 ขั้น

ขั้น 1 เปิดระบบ

ดับเบิลคลิก run.cmd → รอขึ้น: "running at http://127.0.0.1:8205"

ขั้น 2 คัดลอกกุญแจ

รัน copy-token.cmd (token เข้า clipboard โดยไม่โชว์ค่า)

ขั้น 3 เข้าห้องทดลอง + วางกุญแจ

เปิด http://127.0.0.1:8205/lab → วาง Token (Ctrl+V) → บันทึก
ผลที่ต้องเห็น: ป้ายเขียว "พร้อมใช้งาน"

ขั้น 4 สั่งงานแรก

URL: https://books.toscrape.com/
Goal: หาราคาเล่มแรกในหมวด Travel
กด "▶ สั่งทำงาน" → รอ 10–25 วิ (ครั้งแรก AI วางแผน)
ผลที่ต้องเห็น: คำตอบ £45.17 + ทุกขั้นสีเขียว

ขั้น 5 สั่งซ้ำ — เห็นพลังจำสูตร

สั่ง goal เดิม → เวลา planning: วินาที → ไม่กี่มิลลิวินาที · ทั้งงาน 5 วิ (จาก 21 วิ)

บทที่ 2 — ใช้งานประจำวัน

สั่งงานเว็บ

Goal ดี = เป้าเดียว ชัด จบด้วยคำตอบที่ระบุได้ — "หาราคา X จากหน้านี้" ดีกว่า "ดู ๆ ทุกอย่าง"

สั่งงานเดสก์ท็อป

แท็บ Computer Use → ใส่เป้า → AI เปิดโปรแกรมแล้วหยุดโชว์ popup ให้คุณตัดสินใจ → กดอนุมัติถึงลงมือ (ไม่กด = ยกเลิกเองใน ~20 วิ)

Shell (admin เท่านั้น)

คำสั่งระบบผ่าน POST /api/shell-run — ทุกคำสั่งมี snapshot ก่อน-หลัง — ทำพังกู้คืนด้วย POST /api/shell-rollback (พิสูจน์แล้ว: ไฟล์ถูกทำลาย กลับมาเหมือนเดิมจริง)

หยุดงานทันที

กด ⏹ หยุด ใต้งานที่วิ่ง (หรือ POST /api/task-cancel) — AI จบที่ขั้นปัจจุบันโดยไม่เดินหน้า — สั่งงานใหม่ได้ทันที

ตรวจย้อน AI ทำอะไรไปแล้ว

type data\action-manifest\app-YYYY-MM-DD.jsonl   (ทุกคำสั่ง+ลายเซ็น)
python -c "from service import keysign; import glob; print(keysign.verify_chain(glob.glob('data/action-manifest/app-*.jsonl')[-1]))"
→ {"valid": true} = ระเบียนพร้อมรอยเท้าสมบูรณ์ · valid false = มีการแก้ระเบียน — รายงานทันที

บทที่ 5 — ปัญหาประจำวัน → วิธีแก้

อาการแปลว่าทำยังไง
ป้ายเหลือง "ต้องวาง Token"ยังไม่ได้วางcopy-token.cmd → Ctrl+V → บันทึก
ป้ายขาว "หลุดชั่วคราว"server รีเซ็ตชั่วคราวรอ 5–10 วิ — auto-retry เอง
ป้ายแดง "server ปิด"หน้าต่าง run.cmd ถูกปิดเปิดใหม่ — งานค้างไม่หาย (tasklog)
409 "already running"งานเดิมยึด slotรอจบ หรือ /api/task-cancel
403 "shell_execution_disabled"ธง shell ปิด (ค่าปล่อย)ปลดผ่าน Config Version + Approval — ห้ามแก้เอง
401 ทุก calltoken ผิด/คนละเครื่องcopy-token.cmd ใหม่ที่เครื่องนั้น
planning ช้าDGX ไม่ตอบดูสถานะ DGX บน lab — เครือข่าย/DGX บน/ล่ม
งาน ended_at_restartserver ดับกลางงานไม่เดินต่อเอง (fail-closed) — สั่งใหม่

บทที่ 6 — กติกาความปลอดภัยทุกคนต้องรู้

1. Token = บัตรผ่านประตู — ห้ามส่งแชท/อีเมล/สกรีนช็อต

2. ทุกคำสั่ง AI มีลายเซ็นโซ่ — verify แล้ว valid=false = มีการแก้ระเบียน — แจ้งผู้ดูแลทันที

3. ปลดธงอันตราย = ผ่าน Config Version + Approval — ห้ามงัด config.json ตรง

4. UAC ขึ้นให้คนกดเสมอ — AI กดแทนไม่ได้เชิงเทคนิค (secure desktop ของ Windows)

5. lsass/system ปิดถาวรในโค้ด — ไม่มีธงปลด — ใครบอกปลดได้คือของผิดชุดโค้ด/ปลอม

6. ของลับจริงอยู่ในไฟล์สิทธิ์เดียว — ระบบ redact คำสำคัญในผลอัตโนมัติ (token/password/api key)

บทที่ 8 — ก้าวถัดไป

1. อ่าน trace ต่องาน: data/traces/<task_id>.jsonl — ทุกขั้นเก็บ observation/ความมั่นใจ/เวลาแยกชั้น

2. งานต้องล็อกอิน: POST /api/login — ระบบเปิด Chrome ให้ล็อกอินจริง 1 ครั้ง → เก็บ profile ใช้ซ้ำ

3. ลึกออกแบบทั้งระบบ: codex-output/WO-018/designspec.md (requirement/design/framework ทำซ้ำ + บทบาทองค์กร)
